## Assessment summary

First doctoring of Backdoor (never-doctored tier, median surface-score pick). Target shape
written fresh to `Docs/health.md`.

Backdoor is a leaf: it owns one table (the API keys) and everything else it exposes is
translation over four other sections' contracts interfaces. That shape is intact — no
controller here touches a foreign repository, and the auth model is genuinely enforced in one
filter. What the section carries instead is **narration about where its routes used to live**.
The consolidation that created it moved five surfaces in from Debug, Agent, Issues, Feedback and
Surveys, and each move left a "was `/api/X` in section Y" clause behind, plus nine copies of one
comment restating the line under it (findings 4, 5, 13).

Two real defects came out of the target rather than out of a scan. The target's S3 shape says a
list endpoint parses **and clamps** its query; three of the five did, and the two that did not
(`issues`, `feedback`) passed the raw `?limit=` through to a SQL `LIMIT` — on the feedback path
over rows carrying their whole message thread (finding 1). The target's structural rule that a
leaf references exactly the assemblies its types come from caught a `Humans.Issues` project
reference that nothing resolves through: every Issues type the section names comes from the
contracts leaf (finding 3).

The section's test project was strong on the key service and the auth filter and had **no test
file at all** for the feedback controller — seven endpoints, four of them writes that must carry
the key owner as the acting user, which is the one thing Backdoor exists to guarantee
(finding 9). That gap is now closed.

The headline for Peter is finding 18: the issue queue is fetched as a full admin whoever the key
belongs to, so a Board-only key holder reads rows the Issues UI would scope away from them. The
run pinned the current behavior rather than changing it — it is a business-behavior question and
no document states which way it is meant to go.

## Findings (ranked, 3e)

1. **`?limit=` reached a SQL `LIMIT` unclamped on two of five list endpoints.**
   `BackdoorIssuesController.List` put the raw value into `IssueListFilter.Limit`
   (`IssuesRepository` ends in `.Take(f.Limit)`); `BackdoorFeedbackController.List` passed it
   straight to `GetFeedbackListAsync` (`.Take(limit)` over a query that `.Include`s every
   report's messages). Negative and zero values were equally unhandled. The agent, surveys and
   logs endpoints already clamped, so this was a gap in one shape, not a missing policy.
   Both clamped to `[1, 1000]`.
2. **Four wrong or incomplete XML doc comments on the section's own contracts.**
   `IBackdoorApiKeyRepository.TouchAsync` said "fire-and-forget from the auth filter" — it is
   awaited, from `BackdoorApiKeyService.ResolveOwnerAsync`; `EraseForUserAsync` named only the
   creator column when it detaches creator *and* revoker; `IBackdoorApiKeyService.ResolveOwnerAsync`
   did not mention that it refuses on ineligibility or that the last-used stamp happens only
   there; `IssueAsync` did not mention label validation or the active-account half of
   eligibility.
3. **Dead `ProjectReference` to `Humans.Issues`.** Every Issues type named in the section
   resolves from `Humans.Issues.Contracts`, which is referenced separately. Removed, narrowing
   a leaf section's graph by one edge.
4. **Nine identical `// 404 on missing — log Warning per always-log-problems` comments**, each
   directly above the `logger.LogWarning(...); return NotFound();` it describes.
5. **Route-lineage history**, five "was `/api/X` in section Y" clauses plus two "Before #1128

6. **Five unqualified cross-repo refs** (`#631`, `PR 618`, `#1128` ×2, `#750`, `#858`) — cut
   with the sentences carrying them, per `issue-refs-qualified`.
7. **`ActorUserId => GetCurrentUserId() ?? Guid.Empty`** in both machine controllers describes a
   state the auth filter forbids (§3 of the target: a default that can never fire is not a
   safety net). Proposed replacing the fallback with a loud throw. **Reviewer REJECT**, and the
   reviewer was right: `ActorUserId` is read *inside* `try` blocks whose
   `catch (InvalidOperationException)` returns `NotFound()`, so the "loud" failure would have
   surfaced to a client as a spurious "issue not found" — and `UpdateSection` would have echoed
   the message in a 422. Reverted rather than reworked; see the retro.
8. **A rotate's two audit entries were unpinned.** Invariant I4c says a rotate is a revoke entry

23. **`BackdoorApiKeyRepository` has no tests.** Invariants I8b (a revoked key never comes back

24. **`RotateAsync` is not atomic.** It awaits `RevokeAsync`, which commits, and only then
    persists the replacement — a failure in between leaves the owner with no working key. Tiny
    window, trivial recovery ("issue a new key"), so recorded in `Docs/debt.yml` rather than
    fixed; noted because the docs describe a rotate as one operation.
